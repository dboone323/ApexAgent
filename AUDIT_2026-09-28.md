# ApexAgent Fresh Code Audit — 2026-09-28

**Method:** Five parallel read-only auditors over the paired Mac (file access only — no shell, no grep, no compiler). Nothing was compiled, executed, or modified.
**Context:** Follow-up to `AUDIT_2026-09-24.md` and `FIXES_2026-09-24.md`. The 2026-09-24 fix session was never built or run, so every "fixed" claim in this report was re-verified against current source text, not assumed.
**Purpose:** Step 1 of a 3-step plan — (1) this audit, (2) Daniel builds and runs the app in Xcode himself, (3) a live click-through of the running app via computer control. §5 is written to set up step 3.
**Bottom line:** The Sept-24 fixes are mostly present in source, but the fix session appears to have introduced **three probable compile failures** (§3.1) — the project likely does not build right now. Beyond that, the single most serious runtime defect is that dynamic script tools bypass all of the Sept-24 script-execution hardening (§3.2.1).

## 3. LIKELY BUGS

### 3.1 Probable compile failures (fix before anything else)

1. **`ApprovalPolicy.swift` ~139–193 vs ~267–305 — invalid redeclaration.** Two `verdict` overloads share the identical external signature `verdict(tool:summary:governanceProfile:)` (one with internal name `governanceProfile`, one with `governanceProfile profile:` — Swift distinguishes overloads by *external* labels, so this is an invalid redeclaration). The orchestrator's `ApprovalPolicy.verdict(tool:summary:governanceProfile:)` call site is affected too. The third overload (labeled-internal `profile:`) carries the docstring matching the M8 comment — likely the intended survivor. *Fix:* delete the older unlabeled overload (~139–193).
2. **`AgentOrchestrator.swift` ~1523 — invalid closure syntax.** `Task { [weak self] @MainActor in` — attributes must precede the capture list: `Task { @MainActor [weak self] in`. The project's own `AGENTS.md` documents the correct form. *Fix:* reorder.
3. **`PlaybookRunner.swift` ~337–350, ~714–752 — Swift 6 Sendable violations.** `ParallelTaskItem: Sendable` stores `BotSession?`; `BotSession` is a mutable `@MainActor` class, not Sendable; `nonisolated static runLiveTurn(session: BotSession, …)` passes it into task-group children. *Fix:* snapshot needed fields into a Sendable struct before entering the task group. (Medium-high confidence — Swift 6 diagnostics can surprise.)

### 3.2 Critical runtime defects

5. **`DynamicToolbox.executeTool` script branch (`DynamicToolbox.swift` ~222–278) bypasses all Sept-24 hardening.** Spawns `/bin/zsh` with `arguments = ["-c", "\(resolvedPath)"]` where `resolvedPath` is only tilde-expanded from the manifest's `script_path`: (a) **shell injection** — `$(…)`, backticks, or `;` in `script_path` execute arbitrary commands; (b) **no path validation** — no allowlist, no symlink resolution (the hardened `executeDynamicScript` in `MCPClient.swift` ~787–880 does both, but nothing on this path calls it); (c) **no timeout** — `process.waitUntilExit()` unbounded; a hanging script hangs the tool call and task cancellation doesn't kill the child. `execute_dynamic_tool` is `.high` so dispatch is confirmation-gated, but execution is not hardened. *Fix:* route this branch through `executeDynamicScript` (validation + timeout + direct exec without `-c` interpolation).
6. **`ApexGatewayServer` leaks to unauthenticated peers + confirmation hang.** `registerConnection` → `broadcastState()` pre-auth; `broadcastMessage` iterates `connections`, not `authenticatedConnections` (`~111–116`, `~184–304`) — any local process that connects receives full conversation state and live `requestConfirmation` payloads (tool name + arguments) despite token-gated inbound actions. Separately, `requestRemoteConfirmation` registers a checked continuation with **no timeout** — once `confirmationGateway` is installed, a silent client suspends tool execution forever. *Fix:* broadcast only to `authenticatedConnections`; add a timeout resuming `false`.
7. **`VirtualizationMicroVMSandbox.executeInIsolatedSandbox` is not a VM and ignores its timeout.** Temp-dir + sanitized-env local `zsh` (VZ config builder never used here); `timeoutSeconds` accepted but never enforced; `readDataToEndOfFile` on stdout then stderr before `waitUntilExit()` is a classic pipe deadlock if the child fills stderr while stdout drains. *Fix:* enforce timeout (kill on expiry), drain both pipes concurrently, rename/document as process isolation.
8. **Nested confirmation bypass via `confirmationPerformed`.** `AgentOrchestrator.executeToolByName` sets `confirmationPerformed = true` for the whole tool execution (defer-reset). Any *nested* `executeToolByName` in that window — e.g. a delegated sub-agent's tool calls on the MLX/Ollama path (`DelegateTaskTool` → `AgentRequestRouter` → sub-agent loop) — skips both gates. Native engine path unaffected. *Fix:* scope the flag to the outermost call or re-gate nested calls from a different agent identity.
