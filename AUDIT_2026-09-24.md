## Executive Summary

ApexAgent is a large, ambitious, genuinely multi-agent macOS assistant: ~55 registered tools, real MCP stdio client with timeouts/backoff/circuit-breaker/process-supervision, 103 test files, SwiftUI + App Intents + FoundationModels + Apple Containerization integration. The R1–R4 milestone work (PROJECT.md) is **mostly implemented** — playbook models/presets/runner infra, container snapshots, MCP dashboard, creation sheets, and broad test suites all exist on disk.

**But the headline is security + build health, not features.** Two CRITICAL security findings are ship-blockers: `KeychainManager` persists secrets to plaintext `UserDefaults` while reporting Keychain success, and `ApexGatewayServer` binds all interfaces with zero authentication, letting any LAN client drive the agent and self-approve its own dangerous tool calls. Separately, the four 2026-09-11 compile errors are fixed, but the 2026-09-20 edit that fixed them appears to have introduced new Swift 6 strict-concurrency violations — the project likely does not compile right now (unverified by build).

On R1–R4: PROJECT.md marks all milestones M1–M5 **PLANNED**, but code shows 8 of 15 features fully implemented, 6 partial, 1 missing. Conversely TASK_MANIFEST.md marks R1–R4 "✅ Complete" and TEST_READY.md claims "all PASS / 0 placeholders" — both overclaim (see §7, §8).

### 1.2 New probable Swift 6 violations — HIGH (unverified by build)

The 2026-09-20 edit appears to have introduced new strict-concurrency violations that did not exist in the 09-11 log:

- `AgentOrchestrator.swift:715-730` — `currentTask = Task { … }` is a plain nonisolated unstructured task whose body synchronously touches MainActor-isolated state (`self.isGenerating = false`, `self.activeAssistantMessageId = nil`, sync call to `resetSession()`). Under `swift-version 6` + `StrictConcurrency` these are errors.
- `AgentOrchestrator.swift:1480-1487` — `confirmationTimeoutTask = Task { [weak self] in … }` synchronously reads MainActor-isolated `pendingConfirmation` and calls MainActor-isolated `resolveConfirmation` from a nonisolated task.
- `ToolEventLogger.swift:24` — `final class ToolEventLoggerImpl: ToolEventLogger` is not `@MainActor`, but `ToolEventLogger` is a `@MainActor` protocol (line 12). A non-`@MainActor` type likely cannot conform under Swift 6.

## 3. Security Findings

### CRITICAL

- **C1 — `KeychainManager` persists secrets to plaintext `UserDefaults` and lies about failure.** `save(key:value:)` writes to the Keychain *and then unconditionally* to `UserDefaults.standard` (`secure.\(key)`, `Models/KeychainManager.swift:73,96,102-106`), with `if !success { success = true }` — callers are told the Keychain write succeeded even when it didn't. `get(key:)` prefers the in-memory fallback, then the **plaintext UserDefaults value** (`:112-121`), and only then the Keychain. Every "keychained" secret (Gemini/Tavily/Brave keys, tokens) sits in cleartext in `~/Library/Preferences/…`. **Fix:** remove the UserDefaults mirror entirely; never report success on Keychain failure; migrate existing `secure.*` defaults into the Keychain and delete them.
- **C2 — `ApexGatewayServer` binds all interfaces with zero authentication.** `NWListener(using: .tcp, on: port)` with no `requiredLocalEndpoint` (`Models/ApexGatewayServer.swift:34`); `handleClientAction` (`:137-157`) accepts `.sendMessage` (full agent tool execution), `.cancelGeneration`, and `.resolveConfirmation` from **any TCP client**; started in `runDaemonMode()` (`ApexAgentApp.swift:287,314`, port 1337). Any host on the LAN (or beyond, firewall permitting) can drive the agent — and via `.resolveConfirmation` **approve its own dangerous tool calls**, since `init` wires `confirmationGateway` to remote confirmation (`:22-25`). **Fix:** loopback-only bind and/or a pre-shared token handshake before honoring any action. (Also MEDIUM: frame length is an unbounded `UInt32` (`:112-116`) → peer-forced huge allocation, DoS.)

### HIGH

- **H1 — `execute_dynamic_tool` (.medium) executes arbitrary dynamic/MCP shell tools with no user confirmation**, while `create_skill` (which *installs* such scripts) is `.high`/gated — privilege asymmetry (`ApexAgent/Tools/DynamicToolCallTool.swift:24-30`, `ApexAgent/Security/AgentSecurity.swift:24-101`). Promote to `.high` or gate dynamic-script execution.
- **H2 — public `executeDynamicScript` in `MCPClient.swift` (`:~741-775`)**: runs `/bin/zsh <scriptPath>` with **unbounded `waitUntilExit()`** and no path/cwd validation.
- **H3 — `requestConfirmation` test-mode heuristic auto-approves everything via env/argv** (`AgentOrchestrator.swift:1404-1420`): process name contains "xctest", `APEX_TEST_MODE` set, any argv contains "test", etc. Anyone influencing the launch environment (`open --args …test…`, `APEX_TEST_MODE=1`) silently disables *all* human confirmation for destructive tools in production code. Replace with `#if DEBUG`.
- **H4 — `AgentRegistry` data race** (`Models/AgentRegistry.swift:20,153,157,191,196`): `nonisolated(unsafe)` dictionary + `nonisolated` mutating methods (`register`/`unregister`/`allAgents`/`resolve`) — unsynchronized mutation, potential crash. Make actor-isolated or lock-guarded.
- **H5 — PlaybookRunner's agent "turns" are canned stub text, not real agent invocations** (`PlaybookRunner.swift:545-617`, called `:228`, `:310`). The M2 engine executes a workflow *simulation*; its 11 tests assert on canned strings (`contains("Code Architecture")`). Real-session plumbing is proven available (`MultiAgentDebateCoordinator.swift:48-73`, `DispatchSwarmTool.swift:136-160`) but unwired in the runner. Either wire real sessions or relabel the feature honestly.
- **H6 — No UI surface for playbook approval cards.** No playbook views in `ApexAgent/UI/`; the runner suspends at `requiresApproval` stages via `CheckedContinuation` (`:145-148`) with no user path to approve/reject in production.

### MEDIUM

- **M1 — CollaborativeServer: total loopback trust incl. live screenshots** (`/api/screen` serves to any local process, `Models/CollaborativeServer.swift:231-260`); LAN token lives in **plaintext UserDefaults** (`apex.collabToken`). LAN-mode design (token + Host/Origin allowlists + rate limiting) is otherwise reasonable.
- **M2 — WebhookServer binds all interfaces** despite "localhost only" comments (`Models/WebhookServer.swift:50-65`); auth lives in unverified `WebhookRouter`. Set `requiredLocalEndpoint = 127.0.0.1` to match the comments.
- **M3 — 8 orphaned tool structs** not in `ToolDispatchEngine.buildAllTools` and unreachable via standard dispatch: `computer_use`, `github`, `manage_sandbox`, `simctl`, mail, discord×2, deep_link. `ComputerUseTool`'s docstring falsely claims confirmation gating (it's not in `toolRiskMap` either — would default `.medium` → no confirmation for live mouse/keyboard synthesis). Register or delete; fix the stale `container_status` risk-map entry vs the actual `manage_sandbox` name.
- **M4 — MCPKit (Modules/) has a naive duplicate stack:** 56-line `MCPKit.MCPClient` (no timeouts/retry/circuit-breaker/logging) vs the 877-line production stdio `Models/MCPClient.swift`; `MCPInputSchema` defined in both with different shapes; `MCPServerListener` is a hand-rolled **unauthenticated HTTP/1.1 server binding all interfaces** (`Modules/MCPKit/MCPServerListener.swift:74-108`). Consolidate or clearly mark experimental.
- **M5 — ShellTool runs user commands via `/bin/zsh -c`** (both PTY and `Process` fallback, `Tools/ShellTool.swift:106-147`) — no argv-array execution; safety rests on regex screening + confirmation, which `ApprovalPolicy`'s own header admits is *"NOT a security boundary"* (`Security/ApprovalPolicy.swift:10-15`). Working-dir quoting is correct (`:51`); container mode still runs the check (`:36`).
- **M6 — FileSystemTools: no local symlink resolution** (`resolvingSymlinksInPath` never appears; write path doesn't standardize absolute paths, `Tools/FileSystemTools.swift:157-162`); `FileReadTool`'s fallback chain (`:53-99`) can resolve and read a *different file* than the model intended. Symlink defense is delegated to `SecurityAuditor`/`SecurityGovernanceProfile`, whose guards have no observed callers.
- **M7 — `MCPClient.handleTermination` ignores its own config**: hardcoded 60s window / ≤3 restarts (`Models/MCPClient.swift:~522-532`) while `MCPClientConfig` defines `restartRateLimitWindow`/`maxRestartsInWindow` (`:35-36`).
- **M8 — Features 8/10/11 defined but not wired** into live paths (governance verdict overload unused; isolation level write-only; `symlinkTraversal` never thrown; mount-safety guard with no observed callers).
- **M9 — `AppGroupDataBus` hardcodes foreign app-group id** `group.com.dboone323.fleet` (`Modules/SharedModels/AppGroupDataBus.swift:18`) with silent `UserDefaults.standard` fallback — cross-app sharing is effectively dead. (Note: the *entitlements* app-group was fixed to `group.com.apexagent`; this is a separate stale reference.)
- **M10 — `PTYSession` fails open to host PTY** (`Models/PTYSession.swift:185`): if the Apple Container sandbox fails to start, it silently falls back to host execution. Deserves at least a loud log/user warning.

### LOW

- Duplicated `dangerousToolNames` (`ToolDispatchEngine.swift:11` + `AgentOrchestrator.swift:204`); `confirmationPerformed` module-internal; `OrchestratorProvider`→`self` collapse (DI theater); unverified strong-reference cycles orchestrator↔tools/PTYSession; `CollaborativeServer` frame DoS (covered in C2); stale comments (`waitUntilReady` "45s" vs 3s code; "~1,800 LOC" vs ~890; `MCPClient` stderr `print`); `AppGroupDataBus` silent fallback (M9); debug `print`/`fflush` in `DelegateTaskTool.swift:32-33`; three bespoke parallel fan-outs with no shared primitive (`PlaybookRunner`, `DispatchSwarmTool`, `MultiAgentDebateCoordinator`); `TeamPlaybook` vs `CollaborationPlaybook` naming collision; duplicate `AskApexAgentIntent` in `ApexAgentIntents/` (944 B) vs `ApexAgent/Intents/` (2409 B) — same intent name, two modules, AppIntents registration collision risk (contents not diffed).

### Context

`com.apple.security.app-sandbox = false` is deliberate (agent needs Accessibility/Screen Recording/Apple Events). **Every "container"/"sandbox" guarantee in the codebase is policy-only** — enforced by `ContainerManager`/`SecurityGovernanceProfile`, not the kernel. That makes the unwired guards (M6, M8, M10) load-bearing gaps, not cosmetic ones.

## 4. Architecture & Code Health

- **Structure matches the design:** `Runtime/` is a clean request pipeline (Router → PrecedenceResolver → ModelRegistry → ProviderFallbackExecutor → SessionLifecycleManager) with a genuine canonical contract (`AgentRuntimeContract.swift`: `AgentRequest`/`RuntimeEvent`/`AgentIdentity` across GUI/CLI/Gateway/Daemon/Routines/Intents). `Coordinators/` (new 2026-09-21) holds session coordination + tool dispatch. `Models/` holds multi-agent pieces, `Security/` policy + audit (both `AgentAuditLog`/`AgentAuditLogger` are actors — correct). Logical direction is sane: UI/Intents → Runtime → Orchestrator → Coordinators/Models; Security is depended-upon.
- **God object (unchanged since June):** `AgentOrchestrator` (1585 lines, `@Observable @MainActor`) still conforms to both `OrchestratorProvider` and `ToolEventLogger`; the DI indirection collapses to `self` (`AgentOrchestrator.swift:1356`). The June audit's "split the orchestrator" recommendation (IMPLEMENTATION_PLAN.md WS3) was deferred per NEXT_STEPS.md policy — still the biggest maintainability drag.
- **Swift 6:** `@Observable`+`@MainActor` pairing correct across `BotManager`, `ContainerManager`, `GroupChat`, `ToolDispatchEngine`, Router, Runtime; `Sendable` on value types; `MCPClient` is an actor decoupled via the `ToolEventLogger` protocol (prior 3.5 done). Correct `nonisolated(unsafe)` Task storage in the orchestrator. Gaps are §1.2 and H4.
- **No TODO/FIXME/XXX/HACK markers** in sampled files. Filename scan shows no `*backup*`/`*old*`/`*copy*` cruft.
- **Dead/unwired code:** `ApprovalPolicy.verdict(tool:summary:governanceProfile:)` (zero callers); `SecuritySandboxError.symlinkTraversal` (never thrown); `verifyWorkspaceMountSafety` / `validateFilesystemAccess` / `validateCommand` (no observed callers); `ToolEventLoggerImpl` (no-op fallback); 8 orphaned tool structs (M3); `Tools/apexflow` and `Tools/benchmark-repro` orphaned from root Package.swift (documented `swift run` commands fail); XcodePlugin's `ApexAgentMCPServer` is an intentional stub (canned acks, not real execution) and not referenced by root Package.swift.
- **MCP resilience claim is substantially true** for the stdio client: 60s request timeout with force-resume (`:~571-577`), ping watchdog, `0.5·2^attempt` backoff (≤5), health via `tools/list` + `measureLatency()`, circuit breaker (≥3 failures, `resetCircuit()`), `setpgid` + `killpg` SIGTERM→SIGKILL process-group cleanup (prior H5 appears fixed), readiness gates. Blemishes: one raw `print` remains (`:~336`), restart limiter ignores its config (M7), unbounded `executeDynamicScript` (H2).
- **Tool inventory:** `ToolDispatchEngine.buildAllTools` registers **55** tools (`ToolDispatchEngine.swift:24-80`) — README's "47 tools" is stale. Registration is FoundationModels `Tool` structs → `AnyExecutableTool` JSON bridge (`Tool+Logging.swift:133-166`) → dispatch by name with bot RBAC allowlists, global denylist, and enterprise capability tokens. `AgentRegistry` is the *bot* registry, not the tool registry.
